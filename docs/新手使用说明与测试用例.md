# Polymarket Quant Simulator 新手使用说明与测试用例

这份文档是给第一次接触这个项目的人准备的。

你可以把这个系统理解成一套“Polymarket 模拟量化研究平台”，它的目标不是直接帮你下真钱，而是帮助你：

- 看市场
- 拉数据
- 做回放研究
- 跑模拟交易
- 在网页里看过程、状态、结果和风险提示

当前版本是 **simulation-first（模拟优先）**，**不会真实下单**。

新手默认入口是：

```bash
streamlit run app.py
```

这个入口会打开 SuperPolymarket 主页面，默认先看模拟结果，而不是 run_id、manifest、artifact、日志或同步时间线。

---

## 1. 这套系统现在能做什么

### 1.1 市场列表页面

你可以打开网页，查看：

- 当前活跃市场
- 是否还在接单
- question
- category
- liquidity
- endDate
- conditionId
- yes/no token
- 每一列数据来自 Gamma 还是 CLOB

适合做初步筛选。

### 1.2 市场数据平台

系统可以：

- 批量回填历史价格
- 抓当前盘口快照
- 订阅实时数据
- 记录 gap fill（补洞）
- 保留原始事件

你可以在页面里看到：

- 最新 bid/ask
- spread
- midpoint
- last trade
- 最近价格曲线
- 数据来源
- gap-fill 标记

### 1.3 模拟交易引擎

系统支持：

- limit order
- marketable limit
- cancel
- replace
- partial fills
- tick size / min order size 校验
- submit / cancel latency
- 现金、持仓、成交、fee 账本
- realized / unrealized PnL
- conservative mark
- RiskDecision 风控结果

注意：这是 **paper simulation**，不是实盘。

### 1.4 策略运行

系统支持一套策略逻辑跑三种模式：

- `replay`
- `research`
- `realtime_paper`

每次运行都会保存：

- `manifest.json`
- signals
- orders
- fills
- positions
- risk decisions
- 日志
- 指标结果

这意味着你可以回头检查“为什么这次赚了/亏了/没下单”。

### 1.5 SuperPolymarket 主页面

这是当前最适合日常使用的模拟交易 App。

你可以看到：

- 总盈亏、今日盈亏、已实现/未实现盈亏
- 收益曲线
- 当前模拟持仓
- 最近模拟操作
- Polymarket 风格市场卡片
- 告警摘要
- 新手策略配置：风险等级、单次投入、最大持仓数

技术页面仍在 `Advanced / Debug` 中保留，包括运行记录、产物、manifest、日志、系统健康、mode preflight 和调试时间线。

## 2. 你需要准备什么

### 2.1 基础环境

请先确认本机有：

- Python 3.12 或更高版本
- PostgreSQL

### 2.2 安装依赖

在项目根目录执行：

```bash
pip install -e ".[dev]"
```

如果你只想运行，不做测试，也可以：

```bash
pip install -e .
```

### 2.3 数据库环境变量

Phase 2 及以后需要 PostgreSQL。

先设置：

```bash
export DATABASE_URL=postgresql://localhost/polymarket_quant
```

如果你还没有这个数据库，需要先自己创建一个。

## 3. 推荐使用顺序

如果你是第一次上手，建议按下面顺序来。

### 第一步：打开市场列表页面

```bash
streamlit run src/polymarket_quant/ui/market_universe_app.py
```

你会看到：

- 左侧筛选
- 右侧市场表格
- 底部同步时间线

第一次建议先点击 `Sync markets`。

如果同步成功，你会看到市场行出现；如果失败，先看底部 timeline。

### 第二步：准备历史与实时市场数据

先回填：

```bash
python -m polymarket_quant.services.backfill
```

再启动实时采集：

```bash
python -m polymarket_quant.services.realtime_collector
```

这一步完成后，你就有：

- 历史价格
- 当前盘口
- 实时事件

### 第三步：打开市场数据监控页面

```bash
streamlit run src/polymarket_quant/ui/market_data_app.py
```

你会看到：

- 最新状态表
- 价格曲线
- 数据时间线

如果某些行出现 `gap_fill`，说明系统发生过断线补洞，这不是一定错误，但说明这段数据是修补过的。

### 第四步：运行策略

策略运行的典型入口是 Python 代码：

```python
from polymarket_quant.services import StrategyCliService

cli = StrategyCliService("data/runs")
result = cli.run(strategy, "config/phase4.yaml", events=events)
```

如果你暂时不写策略代码，可以先把它理解为：

- 策略读数据
- 产生 signal
- 系统把 signal 转成订单意图
- 模拟成交
- 生成结果文件

### 第五步：打开 Operator Console

```bash
streamlit run src/polymarket_quant/ui/operator_console_app.py
```

这是你平时最应该看的页面。

建议你重点看这几个区域：

1. 顶部状态带
先看有没有出事。

2. Strategy Overview
看当前策略是否在运行、是否 blocked、PnL 怎么样。

3. Positions / Orders
看是否有持仓和挂单。

4. PnL / Exposure
看盈亏、回撤、暴露。

5. Alerts Timeline
看最近发生了什么。

6. Runs / Artifacts
看历史运行和产物文件。

## 4. 页面应该怎么理解

### 4.1 `Run Mode`

表示系统当前的大模式：

- `replay`：历史回放
- `paper`：实时模拟
- `live-disabled`：禁止 live

`live-disabled` 不是实盘模式，它的意思是：**现在不允许往 live 方向走**。

### 4.2 `Connection Status`

主要看四类连接：

- DB
- 市场数据 WS
- 执行层
- 风控层

如果这里不完整，系统可能会阻断新单。

### 4.3 `New Order Status`

常见有三种：

- `allowed`：允许新单
- `partially blocked`：部分阻断，通常是不允许加仓，但允许减仓/平仓
- `fully blocked`：全部阻断

### 4.4 `Critical / Warning / Info`

- `Critical`：严重问题，优先处理
- `Warning`：警告，有风险但不一定立即停止
- `Info`：信息提示

## 5. mode 切换怎么用

Operator Console 里切换 mode，不是直接改一下就生效。

正确流程：

1. 选择目标 mode
2. 点击 `Run preflight`
3. 看系统给出的 blockers / warnings
4. 勾选确认
5. 点击 `confirm mode switch`

如果 preflight 没通过，就不要继续切。

## 6. 常见问题先看哪里

### 6.1 市场同步失败

先看：

- 市场列表页面底部 timeline
- 网络是否可访问 Polymarket API

### 6.2 数据监控页没有内容

先确认：

- `DATABASE_URL` 已设置
- 已执行 `backfill`
- 已启动 `realtime_collector`

### 6.3 Operator Console 里新单被阻断

先看：

- 顶部状态带
- Alerts Timeline
- 是否临近到期
- 是否流动性不足
- 是否连接异常

### 6.4 为什么允许减仓，不允许加仓

这是系统的保守设计。

在临近到期、严重缺流动性等情况下，系统允许：

- reduce
- close
- risk release

但阻止：

- increase exposure

这样做是为了优先降风险，而不是继续开新风险。

## 7.6 用例 F：mode 切换必须先 preflight 再 confirm

### 目标

确认系统不会无检查直接切换模式。

### 操作步骤

1. 打开 Operator Console
2. 选择一个目标 mode
3. 点击 `Run preflight`
4. 查看结果
5. 不勾选确认，直接尝试切换
6. 再勾选确认，重新切换

### 预期结果

- 不做 preflight 时，不能直接完成切换
- 不勾选 confirm 时，不能完成切换
- 只有 preflight 通过且已确认，才会切换

## 8. 最后给新手的建议

如果你第一次用，不要一上来就做策略开发。

建议顺序是：

1. 先把市场列表页跑起来
2. 再把 backfill 和 realtime collector 跑起来
3. 看市场数据监控页
4. 最后再看 operator console
5. 等这些都通了，再开始写策略

这样你会更容易分清楚：

- 是市场同步问题
- 还是数据采集问题
- 还是策略问题
- 还是风控阻断问题
